# NIDOR COMPLETE WEBSITE AUDIT — CURRENT STATE, TECHNICAL RISKS, ECOMMERCE GAPS, AND ROADMAP

## ROLE

Act as a senior full-stack software architect, ecommerce technical auditor, database specialist, security reviewer, UX/UI designer, and ecommerce business consultant.

Your task is to conduct a comprehensive audit of the existing NIDOR perfume and fragrance-decant ecommerce website.

You must inspect the ACTUAL PROJECT and determine its current state.

Do not rely on assumptions, previous plans, intended features, comments in code, or what the project is supposed to do.

Determine what is genuinely implemented and working.

## CRITICAL RULE: AUDIT ONLY

This is an audit and reporting task.

DO NOT:

- Modify application code.
- Modify the database schema.
- Apply database migrations.
- Insert, update, or delete database records.
- Change Supabase settings or policies.
- Change environment variables.
- Install or upgrade dependencies.
- Redesign pages.
- Implement suggested features.
- Deploy the website.
- Perform destructive or state-changing tests.

You may inspect files, configuration, package dependencies, routes, components, SQL migrations, database objects, RLS policies, and available logs using safe, read-only methods.

You may run existing read-only checks, type checks, lint checks, or build commands if they do not modify important project state.

If a test could change data, trigger an external service, create an order, send an email, or affect production, do not run it without explicit authorization.

If you cannot access a particular system or verify a claim, mark it as UNVERIFIED.

Do not claim something works just because its code exists.
